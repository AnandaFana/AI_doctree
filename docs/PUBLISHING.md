# 发布与本地项目隔离

这个仓库发布 DocTree 的程序、协议、通用说明和明确的教学样例。接入项目的源码、论文、实验产物、私有映射和运行历史保留在本机。

## 文件约定

| 内容 | 保存位置 | Git |
|---|---|---|
| 程序、网页、协议、测试 | `doctree/`、`web/`、`docs/`、`tests/` | 提交 |
| 教学项目与默认入口 | `examples/`、`config/projects.json` | 提交 |
| 自有项目副本 | `local-projects/`，或显式忽略的项目根 | 忽略 |
| 本机项目映射与路径 | `config/projects.local.json` | 忽略 |
| 工具状态、审阅历史、备份 | `.doctree/` | 忽略，但须保留和备份 |
| 可选 v2 文档核对基线与最近声明 | `doctree-review.json` | 随所属项目提交；理由不填写凭据或无关私密内容 |
| 原始试点清单、截图、校验日志 | `artifacts/` 及显式忽略的试点材料 | 忽略 |

默认使用 `config/projects.local.json`（若存在），否则使用教学配置；命令行 `--config` 可显式选择。不同配置建议使用不同 `--state-dir`，不把个人路径写进公开默认配置。

## 每次提交

1. 复制自有项目之前，先加入忽略规则。仅扫描目录并不代表允许发布目录内容。
2. 用 `git status --short`、`git diff --cached --stat` 和 `git diff --cached` 核对具体提交；用 `git check-ignore -v 路径` 检查项目、配置与产物。
3. 只提交工具相关的明确路径，检查新增文件是否含真实项目内容、凭据或个人路径。若已跟踪的私有文件需要排除，先保留原文件，再从索引移除。
4. 核对待推送历史。`.gitignore` 和后续删除提交不能让旧提交里的材料消失。
5. 在不含本地项目和本地配置的干净克隆中运行测试、扫描和启动检查。
6. 推送明确的发布分支，例如 `git push origin main`；不要使用 `--all` 或 `--mirror` 发布本地档案分支。

本仓库首次同步采用独立的干净初始提交。本地开发历史另存档案分支，不推送；原始交接与实验记录保留在被忽略的原路径和本地备份中。后续发布沿 GitHub 的 `main` 正常提交，不将本地档案分支合并进发布分支。
